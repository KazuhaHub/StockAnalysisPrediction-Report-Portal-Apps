# 快照清理的假成功：87 份、2.4 GB、零报错

**日期**：2026-11-10
**症状**：`snapshots/` 里 87 个目录，`SNAP_KEEP = 10` 本该只留 10 份。

## 一、先分清「表观」和「真实」

硬链接快照的成本结构很容易看错：

| 指标 | 数值 | 含义 |
|---|---|---|
| 目录数 | 87 | 一次写事务一份 |
| 表观总大小 | 22.0 GB | `du -sh snapshots` 看到的就是这个，**虚的** |
| 真实独占 | **2.38 GB** | 硬链接数 = 1 的文件，只有这些真占盘 |
| 独占所在一 | 9 份 | 其余 78 份独占 0 字节 |
| 零价值份数 | **78** | 与当前 `bars/` 是同一个 inode，`restore` 等于原地不动 |

判别方法（一行）：

```python
own = [f for f in glob.glob(d + "/*.parquet") if os.stat(f).st_nlink == 1]
```

`st_nlink == 1` 才是独占。删掉 `nlink > 1` 的目录**一个字节都不释放**，
所以「删 78 份纯副本」只让目录数好看，2.4 GB 一分不少。

## 二、根因：两处 falsy 判断 + 一处静默失败

### 1. `if years` 把「空列表」和「None」混成一支

```python
want = [str(y) for y in years] if years else [全部分区]   # 空列表 → 拍全库
```

`_new_partitions` 在 `df_new` 为空时会传 `years_want=[]`。本意是「没有分区要保护」，
实际走成「保护全部 13 个分区」。一次空写入 = 一次全库快照。
改成 `if years is not None and not list(years): return`，`None` 才代表全部。

### 2. `rmtree(ignore_errors=True)` 后无条件记录「已删」

```python
shutil.rmtree(d, ignore_errors=True)
gone.append(s["stamp"])        # 删没删成都记一笔
```

在受限环境（后台任务 / 沙箱）里 unlink 被拒，异常被吞，函数照样返回
「清理了 N 份」。这是本库第二次栽在同一模式上——上一次是连续四晚的假成功
（429 被当源端故障、退出码恒 0）。**报成功前必须复查副作用。**

修法：删完 `os.path.exists(d)` 复查，仍在则收集进 `stuck` 并抛 `RuntimeError`。

### 3. 粒度：一只票一份全库快照

补票是**按单票循环调 `add`**，每只票触发一次 `ingest` → 一次快照。
A 批 93 只 = 93 份。若按原计划补完 B 批 1,902 只，就是 1,902 份，
每份新增约 300 MB 旧版本 → 理论 570 GB。清理没生效的话这是必然结局。

## 三、修完之后的行为

| 改动 | 之前 | 现在 |
|---|---|---|
| `SNAP_KEEP` | 10（≈3 GB） | **3**（稳态 ≈90 MB） |
| `snapshot([])` | 拍全库 13 分区 | 什么都不拍 |
| 清理失败 | 静默、报「已清理」 | `RuntimeError`，写入中止 |
| `snapshots` 命令 | 只列表观 mb | 报「真实独占 X MB」+ 每份 `own_mb` |
| 删除后 | 不校验 | 逐份复查目录是否消失 |

保留 3 份的理由：回滚需求是「刚写的这批坏了，退一步」；增量写只增行，
退回第 10 份等于把后面 9 次合法新增扔掉，价值近零。

## 四、这次清理做了什么

- 删除 76 份（其中 68 份纯副本、8 份旧版本），释放 **783 MB**
- 另删 1 份零独占的 4 分区占位 → 再省 0 字节
- 新建 1 份**全库锚点** `20261110-205844-298-anchor-full`（13 分区，独占 0）
- 保留 1 份旧版本 `20261110-012835-740`（304 MB，覆盖 11 分区，缺 2025/2026）
- 终态：**2 份 / 24 个文件 / 真实独占 304 MB**

> 清理过程中目录数在我操作期间自行递减（86 → 82 → 78），`snapshots/.DS_Store`
> 的 mtime 同步刷新，判断是 Finder 里手工删过。`bars/` 无 `.tmp` 残留、
> meta 与日志停在 01:35，确认无进程在写库。

## 六、遗留

1. **keep 会淘汰想长期保留的回滚点**。锚点目前是最新一份，安全；
   但任何 `snapshot --tag 动手前` 拍的手工锚点，三次写入后就会被自动清掉。
   真要长期留存，复制到 `backup/` 而不是留在 `snapshots/`。
2. **`du -sh snapshots` 永远是虚数**。看成本只认 `own_mb`。
3. 空 `df_new` 现在不会拍快照，但也意味着「空写入」本身不再留痕——
   如果将来要追「这次 add 到底动没动库」，得看 `updates.jsonl` 的 `add` 记录。
