## 这一版修掉的硬伤（都会静默污染结论）

1. **股本量纲错乱**：PIT 的 `shares_outstanding` 在中芯国际（差 35×）、华虹（0.5×）、九号公司（10×）等标的上不可用，
   连带 eps / bps / 市值 / PE / PB 全错。改用腾讯快照总市值反推股本，再按「每股指标 × 老/新股本」等比校正。
2. **四象限把「没有结论」算成「又贵又差」**：`upside` 为 NaN 时 `NaN > 0.25` 是 False，`~cheap` 变 True。
   改为先筛可判定样本再分象限，`未分类` 独立计数。
3. **一次性损益做出假低 PE**：数据源无扣非字段，用「TTM 净利率 > 50% 且 净利/经营现金流 > 2」标记 13 只
   （重整收益、处置股权），EP 因子与 PE 类估值对其不适用——否则靠一次性收益的票会顶到价值榜首位。
4. **TTM 自算交叉校验**：按「本期累计 + 上年年报 − 上年同期累计」重算，与源自带 TTM 中位比值 1.000、偏离 >15% 共 0 行，
   确认口径一致（000656 那类 401 亿 TTM 是重整收益的真实结果，不是数据错）。
5. **净资产为负时 ROE 置空**，避免 1309% 这种无经济含义的值参与排名。
6. **对比页在无头浏览器里卡死**：散点 >2k 触发 ECharts 渐进渲染（rAF 逐帧），与虚拟时钟互等 → 页面永久冻结。
   关 `progressive`、抽样到 ~1.5k 点。真实浏览器同样受益（首屏更稳）。
7. **相关性色阶误导**：发散色阶两端插值会让 ρ≈0 变近黑，视觉上「深=高」。改成 负=青 / 0=近白 / 正=红 三色。

已挂定时：**交易日 23:55**（排在 23:30 行情库更新之后）。

### 新增组件

| 文件 | 作用 |
|---|---|
| `asof.py` | 截止日唯一出口：本地 K 线最后一根，或 `PANORAMA_ASOF` 覆盖；报告期从 PIT 面板推导 |
| `snapshot.py` | 固化当日横截面到 `snapshot/YYYYMMDD.parquet` + `market_YYYYMMDD.json` + `index.json` |
| `diff.py` | 对比最近两个交易日 → `data/diff.json`（标签迁移矩阵、榜单进出、位移榜、净变化） |
| `check_freshness.py` | 向服务端交易日历校验「行情库是否已更新到最近交易日」，STALE 直接拒绝发布 |
| `summary.py` | 一行摘要，省得翻日志 |
| `daily_update.sh` | 闸门 → 计算链 → 构建 → 摘要；非 0 退出会指出失败步骤 |

### 日更口径上的三个决定

1. **ASOF 不再手写**。原来 5 个脚本各写一份 `2026-11-13`，日更必然漏改一处，且不报错。
2. **新鲜度校验不能自证**。`ASOF == 最后一根 K 线` 是同义反复——行情库没更新的那晚，它依然成立。
   现在向服务端要 `previous_trading_day` 做外部校验；不通过就 exit 2，不出报告。
3. **价格双来源必须校验**。本地库只覆盖 3,486 只，快照覆盖 5,234 只：只用 K 线会让约 1,900 只丢价
   （实测估值池从 5,148 掉到 3,279，不报错）；只用快照则无法回补历史。
   规则：快照仅在**日期等于 ASOF** 时参与，并校验同日重叠样本价格一致（实测偏差中位 0.000%）。

### 08 今日变化（新增第 9 页）

- 可比样本 = 两日都有估值结论的股票。只算「两日都有行」会把当天缺价的标的算进分母，位移率被稀释。
- 标签净变化限定在可比样本内算，否则「覆盖变化」会被读成「估值迁移」。
- 位移榜要求两日方法数 ≥3，挡掉单一方法给出的极端上涨空间。
- 示例（11-12 → 11-13，全市场跌 1.82%、82.9% 个股下跌）：可比 3,278 只，上涨空间上移 1,685、下移 336，中位位移 +2.1%。

## 补票：把因子体检的样本从 3,578 只补到全市场

### 为什么必须做

`health.py` 的横截面只有约 3,300 只——不是「这些票没有因子」，是**本地行情库只有 3,578 只**。
缺的 2,095 只集中在科创板（399）、创业板（740）、2015 年后上市的沪主板（502）、深主板（100）、
北交所（354），也就是**全是新经济、高估值、上市时间短的那一档**。用 3,300 只算出来的动量 IC、
BP 分位、低波分层，天然缺掉「这几年最活跃的那批票」，这正是样本偏差。

### 缺口构成（2026-11-14 盘点）

| 板块 | 缺口 | 备注 |
|---|---:|---|
| 创业板 | 740 | 300/301 新号段为主 |
| 沪主板 | 502 | 603/605 段，2015 年后 IPO |
| 科创板 | 399 | 688 段，2019 年后开板 |
| 北交所 | 354 | 920 段，2024 年换号；MCP 通道不支持，只有 HTTP 能取 |
| 深主板 | 100 | 001/002 段新股 |
| **合计** | **2,095** | 目标：5,588 只全市场 |

### 三个技术结论（都有实测支撑）

1. **MCP 通道不适合批量补票**。同一份数据、同一个 `batch_id`，MCP `daily_hfq` 单票 284 秒，
   `GET /quotes/daily?return_format=csv` 只要 7~30 秒。差在封装与 JSON 序列化，不在数据。
2. **`volume` 必须取 `volume_raw`**。库内既有行与 MCP 补进来的 154 只，逐日核对都是真实股数；
   而 600519 的 11-10 那行偏偏是 `volume_adj`（差 7.67 倍）。写错这一列，量能类因子整体偏移 factor 倍。
3. **上游吞吐不由我们决定**。行情服务自己挂着一个跑了 230 天没结束的 HKEX 回补任务，
   我们的查询排在它后面，实测 3~10 只/分剧烈波动。所以补票必须是**可续跑**的：
   按票记 `pull_cache/done.txt`，`backfill.sh` 循环「拉一批 → 入库 → 再拉」，缺口清空后自动
   补元数据、重算体检、重建本页。

## 和行情库日更的同步（2026-11-15 00:40）

补票是长任务，横跨了日更时点，两边都得改才安全。

### 冲突点（都是"不报错但脏"的那种）

`update.sh` 与补票 ingest 都是「读全库 meta → 合并 → 整体重写 meta.json」。后写者拿的是自己
开头读到的旧快照，会把先写者新增的票从 meta 里抹掉：bars 还在，但 `md.codes()` 看不见，
补票脚本以为没补过、无限重拉，缺口永远不归零。

另一头是**读者**：分区写入是 `os.replace` 原子替换，读不到半个 parquet；但会读到「一部分票
有今日 bar、一部分还没有」的混合截面——动量与波动因子当场错位，报告看起来一切正常。

### 改法

| 环节 | 机制 |
|---|---|
| 写锁 | 新增 `~/MarketData/locklib.sh`，`.mdwrite.lock` 记 pid + who；`update.sh` 等 900 秒（优先方），补票 ingest 只等 120 秒、拿不到就跳过本轮入库（数据留 `pull_cache`，入库幂等） |
| 拉取 | 补票见 `.update.lock` 暂停 60 秒；`bulk_pull.py` 每 20 只查一次，日更一起来就提前收尾并落盘 |
| 本页 | `daily_update.sh` 取 ASOF 前等 `.mdwrite.lock` 最多 25 分钟，超时 exit 4 拒绝在混合截面上出报告 |
| 闸门 | `check_freshness.py` 除日期外再查覆盖度：11-13 为 4,116/4,379 = 94%，<88% 告警、<60% 判 STALE |

### 顺手挖出的两个老 bug（都不是补票带来的）

1. **周末日更会空转 2.4 小时**。`update` 默认 `end=今天`，周六跑一次 4,276 只票全被判「待更新」，
   每只去要周末 K 线、拿回 0 行。改成 `trading_day.py` 先算最近交易日再 `--end`：
   同一轮从「4,276 只 / 2.4 小时」变成「90 只 / 3 分钟」。
2. **`pending_add.txt` 被写脏**。行尾带 `# RuntimeError(...)`，整行当代码 → `SyntaxError`，
   于是这 6 只票每轮都显示「仍失败」，其实早就在库里。清洗后 7 行只剩 1 只（601268）真失败。
