# 融资盘 · 持仓结构扫描

把「到点就会卖」的持仓结构找出来。单文件离线 HTML，双击即可打开，无需联网、无需安装。

**基准日 2026-11-05｜3,543 只两融标的｜九类被动卖出机制**

---

## 一、这个工具回答什么问题

只回答一个：**抛压会从哪里来，什么时候来**。不判断贵不贵，也不给买卖结论。

起点是孤山鹤舞《融资盘数据：一张表看清杠杆压力在哪》——一个按「融资余额/流通市值」排序的两融压力扫描。我们保留了它的核心视角，但在两处做了根本改造。

---

## 二、核心思路：按「被动卖出机制」分类，不按投资者类型分类

融资盘之所以危险，不是因为它是杠杆，而是因为它**有平仓线**——跌到那个位置就必须卖，不需要任何人的判断。

同一逻辑适用于其他持仓结构：

| 机制 | 持仓结构 | 触发方式 |
|---|---|---|
| **强平** | 融资盘、股权质押 | 跌破风控线，券商/银行代为卖出 |
| **到期** | 限售解禁、定增、员工持股 | 时间一到即获得卖出资格 |
| **套利** | 可转债负溢价、大宗折价接盘 | 有价差就转股/转手，机械执行 |
| **赎回** | 公募重仓股 | 净值下跌→赎回→被迫卖出→净值再跌 |

统一量纲：`room = (1 − 成本线价 / 现价) × 100`。正数表示该线在现价下方 room% 处，负数表示已经跌破。这样不同机制可以放进**同一根价格轴**比较。

### 成本线共振带

**单一指标都只是"一条线"，风险来自多条线重叠。** 当融资强平线与质押强平线同时落在现价下方 25% 以内，再跌一段，卖压来自两套互不相干、彼此不知道对方存在的账户——这不是情绪问题，是合同问题。

**必须按机制去重。** 融资盘的追保线与平仓线是同一批筹码、同一次强平，算成两条线会系统性虚增共振数（这两条线几乎永远同时出现）。所以价格触发型只计**融资强平**与**质押强平**；解禁、强赎、负溢价、大宗折价属于事件型，单独计分。

### 第一处改造：拆出「前瞻脆弱度」，剔除浮亏

原工具的压力排序把**已实现损失**和**潜在风险**混在一起，排在前面的全是已经跌透的票。这些票的融资盘早已触及追保线，**现实中已经被强平过一轮**，存量是洗牌后的残余加新进抄底盘，风险反而释放了。

| | 公式 | 回答什么 |
|---|---|---|
| 已实现压力 `score` | 0.40×拥挤度 + 0.30×加杠杆速度 + 0.30×浮亏深度 | 现在有多紧张 |
| 前瞻脆弱度 `frag` | 0.45×拥挤度 + 0.35×加杠杆速度 + 0.20×价格位置 | 杠杆仍在堆积、浮亏尚未展开的状态读数 |

`frag` 故意不含浮亏。状态分四档，高危只从「临界」里出。**四档都是浮亏深度与杠杆拥挤度的描述性标签，不构成下跌预测**：

| 状态 | 判据 | 含义 |
|---|---|---|
| 临界 | 0 ≤ 距理论追保线 < 15% | 按最激进假设反推的浮亏位置，不是「风险即将来临」 |
| 潜伏 | 距理论追保线 >15%，但占比 >6% 且 20 日抬升 >0.25pp | 杠杆拥挤度仍在抬升、浮亏尚未展开 |
| 已去杠杆 | 距理论追保线 < 0 | 按最激进假设已越线，大概率已洗过一轮 |
| 安全 | 其余 | — |

理论追保线 150% / 平仓线 130% 只对**满仓 80% 保证金的极端账户**成立；全市场平均维持担保比例在 250% 以上，样本期内并未 binding。

**关于「抢跑螺旋」**：2026-11-09 用 120 个交易日、47.3 万条股票-日观测做过专项检验（股票与日期双向固定效应、三套杠杆分组、四道安慰剂），未发现「距理论线某区间 → 融资持有人提前卸杠杆 → 放量加速下跌」的稳定证据；贴线区反而呈缩量（大跌日成交额仅 20 日均额 0.68~0.78 倍）与均值反转，剥掉波动率后距线位置的解释力从 +7.34pp 降到 +1.18pp。详见 `融资盘抢跑螺旋_假说检验.html`。因此个股页并列给出 **20 日波动率分位**与**当日成交额 / 20 日均额**，与静态成本线对照阅读；这三项同样是描述性坐标，不是预警信号。

### 第二处改造：把浮亏连到真实风控阈值

按现行规则反推：融资保证金比例最低 80% → 初始维持担保比例 = (1+0.8)/0.8 = **225%**。

- 追保线 150% → 触发价 = 成本的 **66.7%**
- 平仓线 130% → 触发价 = 成本的 **57.8%**

纯融资盘要跌到成本价的 57.8% 才平仓——比多数人想象的深。真正先发生的是**追保线触发的主动降杠杆**，和浮亏导致的**边际买盘消失**。后者不需要任何人卖出，股价就会失去支撑。

## 三、指标口径

### 融资盘层

| 指标 | 定义 |
|---|---|
| 拥挤度 | 融资余额 ÷ 流通市值（%） |
| 加杠杆速度 | 20 日 Δ(融资余额/流通市值)，单位 pp |
| 估算建仓成本 | 以「融资买入额 × 半衰期 30 个交易日的指数衰减权重」加权收盘价 |
| 距追保线 | (1 − 0.6667 ÷ (现价/成本)) × 100%，负值表示已过线 |
| 融资买入占比 | 近 5 日融资买入额 ÷ 近 5 日成交额（%） |
| 杠杆沉淀天数 | 融资余额 ÷ 近 5 日日均成交额 |

成本估算用指数衰减而非等权 120 日均价：融资盘是**滚动换手**（平均持有期约 1–1.5 个月），等权会系统性低估近期高位加仓。

### 持仓结构层

| 机制 | 指标 | 数据口径 |
|---|---|---|
| 股权质押 | 距质押平仓线 | 单笔质押明细的 `预估平仓线`（≈ 质押日收盘价 × 0.56），按质押股数加权；仅含**未解押**且近 3 年内设立的质押 |
| 限售解禁 | 未来 60/120 日解禁占流通市值 | 解禁数量 × 现价 ÷ 流通市值 |
| 可转债 | 转股溢价率、距转股价、距强赎触发 | 可转债比价表 |
| 大宗交易 | 近 30 日成交额占流通市值、加权折价率 | 折价 >5% 且占比 >0.5% 视为折价出货 |
| 股东户数 | 户数增减比例、户均持股市值 | 多数标的按旬更新；户数增而价跌 = 派发 |
| 公募持仓 | 占流通股比例、持有基金家数 | 季报重仓（2026Q3） |
| 回购 | 计划金额占比、回购价上限空间 | 承接力量 |
| 增减持 | 近 120 日重要股东净变动占流通市值 | — |

## 四、局限（必读）

- **日频快照，非实时。**两融为交易所 T+1 披露。
- **成本与分级都是启发式。**不基于真实持仓明细，是统计推断。
- **距追保线是压力上限估计。**只对"纯单票满杠杆"成立。实际账户多为分散持仓、混合担保，真实压力低于此值。
- **质押平仓线是估算值。**按质押率 40%、平仓线 140% 反推，实际质押率在 30%–60% 间浮动，个体误差可达 ±30%。质押数据为周度快照，期间新增质押未反映。
- **未来解禁市值按现价估算**，实际随股价变动；解禁不等于减持，只是获得卖出资格。
- **流通市值是推算值，不是每日抓取值。**`data/float_shares.parquet` 存流通股本底表（由 `fcap_base / close_base` 反推，与股东户数表总股本交叉校验：3504 只、比值中位 0.9977、≤1.05 占 99.14%），当期按 `fcap_T = fcap_base × close_T / close_base` 由日线推算，历史值再按 `close_t/close_T` 倒推。用比值可抗复权基准整体缩放。流通股本是慢变量，解禁/增发/送转密集期需重跑 `analysis/build_float_shares.py` 校准；已核出 24 只失真标的，集中在 ST 股与 2026 年新上市次新。
- **定增价、员工持股成本价没有结构化数据源**，需逐份公告提取，当前版本未纳入——这是共振带最主要的缺口。
- **北向持股自 2024 年 8 月起改为季度披露**，无法日频监控，未纳入。融券在转融券存量了结后规模萎缩，仅列示不参与打分。
- **已剔除 ETF 与 LOF。**ETF 融资盘以套利对冲为主，不会强平，纳入会污染排序。

### 定时任务（周一~周五：09:00 执行 → 09:33 校验）

**双层设计：launchd 干活，WorkBuddy automation 验收。**

| 层 | 时间 | 职责 | 为什么是它 |
|---|---|---|---|
| launchd `com.wfeixu.marginscan` | 09:00 | 真正执行 `update.sh` | 不依赖 WorkBuddy 是否在运行、是否有活跃会话；睡眠/关机错过时点会**唤醒后补跑一次** |
| WorkBuddy automation | 09:33 | 校验 + 兜底补跑 | 能读懂结果并用人话汇报；发现 09:00 那次没跑才补，正常就只报一行结论 |

`update.sh` 内置 `.update.lock`（存 pid + 存活检测），两层即使撞车也不会并发写 parquet，后来者直接跳过。

**安装 launchd（只需一次，必须在真实 Terminal.app 里执行）**

```bash
bash ~/WorkBuddy/2026-11-07-06-52-22/margin_scan/setup_launchd.sh
```

⚠️ **不能在 WorkBuddy 的对话框里跑**。实测该 shell 不在用户登录会话（`launchctl list` 返回 0 个任务），`launchctl bootstrap` 一律返回 `5: Input/output error`，沙箱外执行、AppleScript 进入 GUI 上下文都一样失败——是会话隔离，不是 plist 问题（`plutil -lint` 通过、`launchctl enable` 返回 0）。

```bash
# 查看状态
launchctl print gui/$(id -u)/com.wfeixu.marginscan

# 立刻手动触发一次（不等 09:00，约 8-9 分钟）
launchctl kickstart -p gui/$(id -u)/com.wfeixu.marginscan

# 停用
launchctl bootout gui/$(id -u)/com.wfeixu.marginscan
```

| 项 | 说明 |
|---|---|
| 触发时间 | 周一~周五 09:00（`StartCalendarInterval` 用 Weekday 1–5；注意 launchd 里 1=周一、6=周六，不是日历软件的排序） |
| 日志 | `logs/YYYY-MM-DD.log`（每次运行一份），`logs/launchd.out.log`、`logs/launchd.err.log`（launchd 层） |
| 完成通知 | 成功后 macOS 通知「融资盘扫描已更新　基准日 xxxx-xx-xx」；失败通知附带退出码 |
| 并发保护 | `.update.lock` 存 pid，若上一轮仍在跑则本次直接跳过 |

**为什么放早上而不是当晚**：两融明细是 T+1 披露，**上交所当晚可获取，深交所要到次日上午**，脚本要求沪深同日齐全才落库，当晚跑只能拿到 T-1 的数据。

**为什么是周一到周五（2026-11-14 修正，原为周二~周六）**：每次跑覆盖"前一交易日"的数据。原排期 Weekday 2–6 意图是"周二补周一、…、周六补周五"，但周六上午拿不到周五的深市数据——2026-11-07 09:04 查 `20261106`、2026-11-14 09:30 查 `20261113`，两次都是沪市已出 2,000 行、深市返回 0 行。结果是周六这一跑必然空转（11-14 那轮抓满 4,198 只日线，基准日照旧停在 11-12），而周一不跑 → 周五数据首次成报要拖到周二。改成 Weekday 1–5 后：周一 09:00 取上周五（深市届时已齐，2026-11-10 跑出 `as_of=2026-11-09` 即同类情形），周二至周五各取前一日，每个交易日都有自己的成报。

> **自动化不是绝对的**：若某天 WorkBuddy 没开且 launchd 未安装，那一轮就是静默不跑。09:33 的 automation 会读 `meta.generated_at` 判断"今天跑没跑"，没跑就补——但如果连 WorkBuddy 也没开，兜底同样失效。**真正抗睡眠、抗未启动的只有 launchd 这一层。**

> **披露时间差（实测）**：上交所 T 日数据当晚可获取；深交所要到 **T+1 上午**，且周五数据更晚——2026-11-07（周六）08:42 复测，11-06 上交所已有 2,000 行、深交所仍返回 0 行（11-05 深交所有 2,119 行）。脚本要求沪深同日齐全才落库，所以时点定在 09:00。若长期仍滞后，把 `BYHOUR`/`Hour` 顺延到 9:30 或 10:00 即可，脚本会自动取最新可用交易日，不会报错。

### 2026-11-12 稳定性改造（事故复盘）

09:00 那轮两融明细已成功落盘，却在抓全市场快照时被东财断连（开盘前 `clist` 翻页到第 3–4 页即 `RemoteDisconnected`），整条流水线退出码 1；随后补跑时 `--refresh-bars` 先删库再全量重抓，限流下只成功 3193/4198 只，**丢掉 1005 只历史**且混入当日盘中 K 线，首份产物池塌到 2702 只、融资余额只剩 15996 亿。已回滚修复，并做四处结构性改动：

| 改动 | 内容 |
|---|---|
| 流通股本底表 | `fcap` 由底表按日线推算；`fetch_spot` 默认不再请求 `clist`（仅 `--refresh-spot` 才抓）。原式 `scale = close_T/close_last` 因 `close_last == close_T` 恒为 1，等价于「每天必须抓到快照」 |
| 日线原子写入 | 不再 `unlink`；写临时文件 → 目标日覆盖率 ≥98% 才 `os.replace`；未通过时旧表为权威、只补缺 |
| 防盘中 K 线 | K 线请求带 `end=两融最新基准日`，并过滤 `date > target` |
| 两道质量闸门 | 计算前查基准日一致／覆盖率／日期连续性；写产物前查池只数(±5%)、融资余额(±10%)、基准日倒退，任一异常 `SystemExit`，保住上一版 HTML |

验证：`analysis/test_bars_gate.py` 10/10（含全失败、部分成功、混入盘中 K 线）、`analysis/test_quality_gate.py` 10/10（含池 2702／余额 15996 被拦下）、`analysis/test_spot_skip.py` 6/6。新口径下公募占比自校验中位偏差由 0.014% 降至 0.000%。

**已知代价（有界）**：`spot.parquet` 不再每日更新，而股票池筛选依赖它提供 `name`，故新进入两融标的的新股最多滞后 **7 天** 才入池（`fetch_spot` 超过 7 天会自动尝试刷新，失败则降级用缓存、不阻断）。池只数若持续萎缩会被闸门 B 的 ±5% 捕捉。校准入口：`bash update.sh --refresh-spot` 后重跑 `analysis/build_float_shares.py`。

**调度维持 09:00 不提前**：上文实测 2026-11-07(周六) 08:42 深交所 11-06 数据仍返回 0 行，09:00 才是可齐备时点，且早于 09:33 的巡检；底表落地后限流依赖已消失，挪时点解决的不再是真实瓶颈。
