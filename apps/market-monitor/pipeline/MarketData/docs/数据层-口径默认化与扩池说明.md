## 2. 三处改动

### 2.1 `test` / `test-all` / `ic` / `stab` 默认 `--list-years 3`

新增 `qsr.LIST_YEARS_DEFAULT = 3`，以及**唯一建池入口** `_load_test_universe()`。
四条命令共用它，`tests/test_test_universe.py` 用**源码扫描**锁住——
漏传一处不报错，只会得到一份口径不同的 IC 或稳定性，这是最难发现的一类错。

三处护栏全是报错而非静默跳过：
- `min_list_years` 不给 `start` → 报错（没有起点，「上市满 N 年」只能按今天算，语义完全不同）
- JSON 池没有 `list_date` → 报错（不静默全剔、也不静默跳过）
- 过滤池 <40 只 → `bias` 拒绝出表

口径写进每条 `tests` 记录（`listing_filter`），报告的样本行会打出来。
`--list-years 0` 可复现旧结论；`lr` 默认保持 0（它评估"今天能不能按这个赔率下注"，
用当前可交易池更贴题），要跟判定同口径就显式传 3。

`doctor` 的池子一致性检查同步改口径：不再拿 `len(univ)` 直接比 `n_stocks`
（永远不等，警告会变成常驻噪音），改成按每条信号的 `universe_start` + 过滤年限重算期望池。

**验证**：`test SIG-002` 换默认口径后逐项复现 `bias` 的过滤池列——
1,054 只 / Δ +2.17pct / t 43.75 / 组合年化 +4.14% / PROMOTE。

### 2.2 扩池：按「对当前口径有没有用」切四批

| 批次 | 定义 | 只数 | 处理 |
|:---|:---|---:|:---|
| A | 现存缺口 · 上市早于 2015-01-01 | 1,285 | 补 |
| B | 现存缺口 · 2015 后上市 | 1,902 | 暂缓（默认口径下进不了样本） |
| C | 退市 · 终止日在库区间内 | 257 | 补 |
| D | 退市 · 早于 2014-06-03 | 80 | 跳过 |

划分依据不是数量而是**决策相关性**：B 批补进来也会被 `--list-years 3` 剔掉，
真需要时 `--batch B` 一条命令的事。

执行上拆成 `--stage pull` / `--stage ingest`：`ingest` 要原子替换 `bars/*.parquet`，
在受管环境里需逐次审批，**后台任务拿不到审批**，会以
`PermissionError: Brokered host rename source refused by file policy` 失败——
而且报在 ingest 阶段、看着像数据源问题，实际一只都没入库。

实际入库 1,449/1,542（94%），93 只卡在上游 429，清单留在 `pending_add.txt`。

### 2.3 退市标记与上市日必须一起写

`meta.stocks[code].status = "delisted"` + `delist_date`，**同时用 `pool_gap.json`
补 `list_date`**。原因：`fill_meta.py` 的数据源是**现存**名单
（`stock_info_*_name_code`），退市股不在里面；退市股缺 `list_date` 会被
`filter_listing_age` 判成「无法证明当时已上市」整只剔掉——数据补了、样本为零。

`market_data.update()` 同步跳过 `status=delisted`：它们的 `last` 就是终止上市日，
往后每天都是空请求。

## 3. 扩池照出来的两个 bug

### 3.1 `action_flag` 只告警、不拦 → SIG-012 差点以反向信号晋级

换总体后 18 条里 6 条改口，5 条是 `REJECT ↔ INSUFFICIENT` 互换（本质都是"没通过"），
真正的问题在第 6 条：

> **SIG-012「量能趋势上行」`vtrend > 1.3`，`action=long`，触发后未来 5 日收益
> −0.30pct、t −4.90——方向是反的，却从 WATCH 升到 PROMOTE。**

原因不是算错，是判定逻辑少一道闸：`action_flag`（"动作可能用反"）算出来了、
也打印了，但**从不参与 `verdict`**。于是「|t| 过阈值 + 样本外同号 + 中性化后同号 +
超额覆盖成本」四项全过，唯独方向相反，照样晋级。

旧池 n=1,988 时它的 |t| 只有 3.66、非重叠点偏薄，卡在 WATCH 上把这个洞盖住了；
扩池把 |t| 顶到 4.90，洞就露出来了。

修法：`judge()` 在 `|t|` 门槛之后加一道——`action_flag` 非空直接 `REJECT`。
`target=absmove` 不受影响（SIG-002 的 `long` 是风险刻画，不是看多）。

**顺带发现**：当前 18 条里 **13 条**带"动作可能用反"告警。其中 12 条效应本身
不显著（|t| 过不了阈值），只有 SIG-012 曾经走到 PROMOTE。也就是说绝大多数是
「噪声方向为正但动作写成了回避」，属于登记时的动作没想清楚，不是策略问题。

### 3.2 成交量单位不统一（100 倍）

`doctor` 的 `amt_real` 从 100% 掉到 98%，报「vwap 落在 [l,h] 内仅 0%」。

| 入库路径 | `volume` 单位 | `amount/(volume×100×close)` |
|:---|:---|:---|
| `ss_cache` 迁移（早期 1,521 只） | 股 | ≈0.01 |
| `stock-server daily_hfq` 直补 | **手** | ≈1 |

差 100 倍且不报错：这批票 `vwap = amt/(v×100)` 大 100 倍、落在 `[l,h]` 之外，
`v` 又小 100 倍。79/3,308 只，绝大多数是刚补进来的退市股。

修法：`qdata.norm_volume_unit()` 按比值判一次统一到「股」。用比值不用代码段/上市日
——两个数量级的差距，阈值 0.3 打不穿。修完 `amt_real` 回到 **100%**，`vwap`/`adv20` 恢复可用。

**这个修复动量能类特征，所以 `test-all` 又重跑了一轮**，判定结果与修复前完全一致
（比值类特征不受影响），符合预期。
