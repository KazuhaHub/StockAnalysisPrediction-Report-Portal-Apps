# 数据层 · 零成交日与复权断点修复

**时间**：2026-11-08 15:50 发现，16:12 修复完毕
**起因**：整理目录时顺手核对「成交量单位」，查出一条更严重的问题
**影响面**：630 只票 / 768 行，被抹掉的假收益中位 −0.5%，极端 −75% ~ +705%

---

## 1. 怎么发现的

原本只想确认一件事：`volume` 到底是「股」还是「手」。做法是查单位一致性
`r = amount / (volume × close)`，全库中位数应该是 1。

结果里出现了 5 个 `inf`（`volume=0` 但 `amount>0`），顺着这条线查下去，
发现全库 **244,116 行（2.7%）零成交行**，而其中 768 行的收盘价与前一交易日不同。

停牌日没有交易，价格凭什么变？

## 2. 根因：股本变动被价格吸收，因子没跟上

以 600381 为例：

```
2014-06-26  17.0410   volume=0   factor=8.1928
2014-06-27 137.2296   volume=0   factor=8.1928   ← 涨 8 倍，仍然没有成交
2014-06-30 137.2296   volume=0   factor=8.1928
```

那天公司缩股（重整），每股价格从 2.08 元变 16.75 元，**股数同步减到 1/8**，
投资者的实际收益是 0。后复权序列本应保持 17.04 不变——靠的是 `factor` 跳 8 倍。
但源端的 `factor` 那天没动，于是后复权价直接涨了 8 倍，凭空多出一根 +705% 的收益。

000007 是相反的形态：停牌期间先跌到 1/3（因子没动），**复牌时源端才补上**
`factor 8.03 → 12.05`（正好是要补的 ×1.5）。

两种形态必须分开处理，否则修一个坏一个。

## 3. 修法：价格拉平，因子吸收

```
C = 前收(已修正) / 本行收盘
本行及后续行：OHLC ×= C，factor ×= C
```

- 后复权价 `OHLC×C` ＝ 前收 → 序列连续 ✓
- 真实价 `(OHLC×C)/(factor×C)` → **完全不变**，没有篡改事实 ✓
- 停牌期后复权价格恒定，天然满足「无成交＝无收益」 ✓

### 三个细节，都是踩过的

| 细节 | 怎么错的 | 怎么改 |
|---|---|---|
| **必须传播** | 只修断点那一行，断点顺移到下一行（复查仍有 767 行）。600381 缩股后价格一直是 137，每行都会被重新判成断点 | 把 `C` 传到后续行，直到源端自己更新因子 |
| **必须能撤销** | 000007 复牌时源端补了因子，若继续乘我们的 1.5，之后整段被放大 1.5 倍，复牌收益从 −10% 变成 +35% | 遇到「有成交且因子相对上一行变化」→ `C` 归 1 |
| **判别用已修正的前收** | 用原始前收判断，一段停牌里的第二根就开始漏 | 前向走，`prev` 用修正后的值 |

另外 `rebuild_partition` 需要 `tradestatus` 列，第一版 `fix_adjbreaks.py` 的
`COLS` 里漏了它，写盘时 `KeyError` 中止——好在写前有快照、且失败发生在写之前，
`check` 复查零损伤。

## 4. 结果

```
复权断点     768 行 / 630 只  →  0
denormal     967 行（5.877e-39）→  0
改动行数     33,293 行（含传播），真实价全部不变
全库 |收益|>50%   329 例 → 127 例（真事件 + 缺股本数据无法判定的有成交日断点）
全库 |收益|>25%   333 例 → 170 例
收益发生变化的行  1,505 行，其中 2018 年后仅 54 行
行数/票数    9,113,716 行 / 3,486 只，一根没少
```

清单落盘在 `docs/adjbreak_fixed_20261108.csv`（768 行：code / date / 原值 / 修正值 / 被抹掉的假收益）。

这份清单是**修完之后反推回来的**，不是当次运行直接写的：第一版脚本按日期命名，
第二次 `--apply`（补跑 2024–2026）发现 0 个断点，用空文件覆盖了第一次的 630 行证据。
补救办法是利用修复留下的指纹——「因子跳了、价格却与前收相等」就是被修过的行，
`k = factor_t / factor_{t-1}`，假收益 `= 1/k − 1`。重建后与首轮报告完全一致（768 行 / 630 只）。
脚本已改成「本次没有断点就不写文件」，时间戳精确到分钟。

**为什么不顺手改掉那 127 行极端收益**：零成交那一类已经修完，剩下的分成两半——

- **真事件**：002506 协鑫集成 2015-08-12 是 `*ST超日` 重整复牌、股本 1 拆 3、无涨跌幅限制，
  +1975% 是真的。把真事当异常抹掉，等于用「看起来不合理」当证据。
- **有成交日的断点**：全库有 153 行（148 只）单日 |收益|>30% 且当天**有成交**，其中 86 行的
  `factor` 与前一日完全相同——真实价一天涨 738%（000520 2015-12-18）在 A 股不可能，
  所以也是因子缺失，只是发生在交易日。

后一类**修不了**：要修必须知道那天股本是缩了还是拆了，而库里没有股本数据，
`factor` 又是错的。任何「把它拉平」的假设都会同时抹掉真的重组复牌（这类票复牌当天
真实涨幅可以到几倍）。所以只记录、不处理，由下游决定：

- `qsr doctor` 已经把这类票**整只剔除**（2026-11-08 报 154 只，含 K 线不足 400 根的），
  判定结果不含它们；
- 单票研究遇到「一天翻倍」先查 `factor` 有没有变，没变就是断点，别当收益。

## 5. 顺带确认的两件事

**`volume` 是复权股数，不是真实股数。** 全库 `amount/(volume×close)` 中位 1.0017，
说明源端把成交量也按因子缩放了。真实股数 = `volume × factor`：

| | 茅台 2026-11-06 | 平安银行 2026-11-06 |
|---|---|---|
| `volume` | 558,551 | 1,202,894 |
| `factor` | 7.671 | 136.36 |
| 真实股数 | 4.28 百万股 ✓ | 1.64 亿股 ✓ |

直接拿 `volume` 排流动性，长历史票会被系统性低估（平安低估 136 倍），
而且低估幅度随上市年限单调上升——这会污染排序，不是噪声。

**停牌日有 bar，只是零成交。** 旧 README 写的「停牌日没有 bar」是错的。
`tradestatus` 全库恒为 1，也不能用来判断停牌——只能用 `volume`。

## 6. 复查节奏

断点新增速度约每年 2–5 例（2022 年后），所以不需要每天查：

```bash
python3 ~/MarketData/fix_adjbreaks.py          # 40 秒，只报告
python3 ~/MarketData/fix_adjbreaks.py --apply  # 确认后写回（自动快照）
```

判断要不要跑的触发条件：**某只票出现「当天没成交却涨跌超 5%」**。
`test_market_data.py` 里三条新测试把这个算法钉死了（传播、撤销、不动正常行）。
