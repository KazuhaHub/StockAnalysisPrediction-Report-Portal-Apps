# 《全市场财务横截面物化 PIT 面板需求 v1.1》评审反馈

评审方：quantwin
评审日期：2026-10-31
结论：**同意按 v1.1 立项，架构方向予以采纳；以下 4 项必须修改或补充后方可冻结需求，其余为需确认项。**

---

## 一、总体评价

v1.1 相对初稿的三处改进是正确的，可直接沿用：

1. **时点驱动而非报告期驱动**：`as_of` 为主参数、服务端做装配（回退、延期、跨期拼接），PIT 正确性收在服务端一次做对，客户端不会用错；
2. **弱 PIT 语义明确**（时间严格 + 数值最新口径）并配 `available_at_quality` 分级，消费方可按质量选择，比"一刀切"更可控；
3. **更正防前视约束（§3.3）**、`changes` 增量流、`coverage` 自检，均覆盖了实际使用中最容易出错的环节。

缺失值 `null`、累计不预年化、预计算落库、性能目标（单页 ≤1s、全量 ≤2 分钟）均认可，无需调整。

## 二、必须修改（P0，改完冻结需求）

### P0-1 历史深度：接受不回补，但接口契约需覆盖"拼接"

我方接受"2023Q4 起、不回补历史"的数据边界，不再要求回补 2012 年。但由此产生的使用方式是**双源拼接**，请在需求中明确承诺：

1. 面板完整覆盖 2023-12-31 至 2026-09-30 共 12 期，每期行数完整、无截断；
2. `/pit/panel` 原始访问端点必须可用（我方本地整缓存后自行装配），而不是只提供 `cross-section` 装配结果；
3. **与 AKShare 历史数据的口径必须对齐**：`net_income` 用**归母净利润**、`bps` 用**归母权益**（详见 P0-3）。若两源口径不一致，拼接点（2023Q4/2024Q1）会产生因子突变，我方无法使用；
4. 请在交付说明中给出拼接建议：我方以 2023Q4 / 2024Q1 / 2024Q2 三期做重叠校验，差异 >2% 的股票需能定位原因（追溯调整 / 口径差异 / 单位差异）。

影响说明（供开发商理解优先级，不属于需求变更）：我方模型训练窗口为 36 个月已到期标签 + 60 个月因子 IC 回看，2024-05 起的截面到 2026-10 仅约 26 个已到期月份。因此 2024–2027 年之间我方无法基于新面板单独出信号，历史段仍用 AKShare。该接口的价值是**从 2024 起替代 AKShare 的增量与 PIT 正确性**，请按此定位验收。

### P0-2 退市股：接受不回补，但必须可监控、可扩展

我方接受"当前库内无退市股数据"。要求：

1. 每个响应必须带 `universe_note`（v1.1 已设计，保留）；
2. `coverage` 端点必须给出"应有股票数 / 实际股票数 / 缺口数"，且并按报告期逐期给出，供我方在报告中声明存活偏差；
3. 面板表**保留 `is_delisted` 字段**（本期恒为 false 即可）。v1.1 将其移出范围，但后续补退市股时若字段缺失会导致接口变更，建议预留字段而不承诺数据。

### P0-3 口径核验必须在编码前完成，且结论固化

`§6.3` 列出的 4 项核验点中，第 1 项（`net_income` 归母 / 合并）是**阻塞项**：

- 我方 `ep` 因子的原口径是 AKShare"基本每股收益"（归母口径）。若面板用合并净利润计算 `eps`，全市场 `ep` 排序会系统性偏移，直接影响选股结果；
- 同理 `bps = equity / shares_outstanding` 中的 `equity` 必须是**归母权益**；
- 请抽 5 家已知公司（建议贵州茅台、中国石化、工商银行、比亚迪、宁德时代，覆盖少数股东权益占比差异大的样本）对公开年报核验，并在字段注释、openapi schema、本文档中固化结论；
- `publish_date` 一致性核验（§6.3-2）与延期宽限参数校准（§6.3-3）同批完成，结论写进交付记录。

**我方已完成一次 Wind 交叉验证（2026Q2，50 只，按申万二级行业分层抽样），可作口径基线**：

| 字段 | 结论 | 说明 |
|---|---|---|
| `eps` / `bps` / `gross_margin` / `rev_yoy` / `np_yoy` | 50/50 全部一致（相对误差 <2%，多数到 4 位小数完全相同） | AKShare 与 Wind 同口径，归母口径假设成立 |
| `roe` | 9/50 超 2%（相对），但绝对值差 ≤0.66pp | AKShare 为期末口径，Wind 为加权平均口径；建议面板以 `net_income/equity` 复算并注明公式 |
| `bps` | 1/50 异常（920003 中诚咨询：6.5897 vs 9.2256，差 40%） | **根因已定位**：该股 2026H1 IPO 增发，AKShare 用**最新总股本** 90,600,000 股做分母，Wind 用**报告期末总股本** 64,714,286 股。后者才是时点正确口径 |

由此追加一条硬约束：`shares_outstanding` 必须是**报告期末总股本**（v1.1 §7 已如此定义，请勿为"与行情软件一致"改为最新股本），否则每股类指标会带入未来股本的前视偏差。我方留存的历史 AKShare 数据在股本变动样本上存在该前视，面板上线后将以面板口径为准。

### P0-4 行业字段必须给出明确方案

v1.1 将 `industry` 移出面板，但 quantwin 的横截面输出依赖行业（行业中性化、行业分组统计）。请二选一并写清：

- 方案 A：面板保留 `industry`（注明"最新分类、非时点"，quantwin 在报告中声明该限制）；
- 方案 B：明确对接 `get_industry_membership_as_of`（REQ-07.2），并给出该端点的路径、参数、返回字段（至少 `instrument_id / industry_code / industry_name / effective_from / effective_to`）。

仅写"另行对接"不足以保证联调，需给出可调用的接口契约。

## 三、需确认项（P1，不阻塞立项，但需在 M1 前答复）

1. **`report_period` 格式不统一**：面板列为 `2026-09-30`，`cross-section` 过滤参数写 `YYYYMMDD`。quantwin 内部统一用 `YYYYMMDD`，请统一为 `YYYYMMDD`，或声明两种都接受并各自返回原样。
2. **`available_at` 生效日**：quantwin 现行规则是"实际披露日 + 1 天生效"。请明确接口返回的是公告日还是可见日；若为公告日，请在 openapi 描述中写明"客户端需自行 +1 天"。
3. **`include_delisted` 参数**：当前为 no-op，易造成调用方误判。建议移除该参数，或在文档中显式标注"预留、当前无效果"。
4. **§3.3 更正约束的实测影响面**：请在 M2 前给出 `data_change_log` 实测数据——`old_hash ≠ new_hash` 影响的 `(instrument, report_period)` 行数占比，以及"更正导致的截面回退"平均回退期数。若影响行数 >5% 或平均回退 >1 期，请提供 `revision_guard` 开关（`on/off`），让消费方可选严格模式或宽松模式。
5. **`changes` 端点的游标语义**：需明确游标是 `changed_at` 单调递增还是复合游标；重复消费是否幂等；`data_change_log` 563 万行需索引 `(domain, changed_at)`，请说明查询性能。
6. **当期未完整期的标记**：2026Q3 截至 10-31 为 4,938 条（未达 ~5,500），请提供"该期是否完整"的标记（如 `is_complete` 或 `latest_complete_period`），避免客户端把不完整截面当成完整截面使用。
7. **§4.3 SQL 拼写**：`PARTITITION` → `PARTITION BY`（笔误，请修正后再实现）。

- **M3**：派生字段边界 + `changes` 端点 + 增量挂钩；
- **M4／M5**：验收与回归，保持原样。
